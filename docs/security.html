Rate limits, PKGBUILD checks, and limits

The repository file docs/security.md is the review note. This page is the operator's version. Neither one is a certification.

Rate limit

TAUR_RPC_RATE_LIMIT=300
TAUR_RPC_RATE_WINDOW=60
TAUR_AUTH_RATE_LIMIT=20
TAUR_TRUSTED_PROXIES=10.0.0.0/8

Defaults are on: RPC 300, auth 20, git HTTP 60, JSON API 120, dumps 12, MCP 60, gRPC 300, and 30 new embedded SSH connections, each per 60 seconds. 0 disables one class. HTTP 429 includes Retry-After. The RPC body is still JSON with "error":"Rate limit reached". X-Forwarded-For is ignored unless the TCP peer is in TAUR_TRUSTED_PROXIES, and that proxy must append the client or every client behind it shares one bucket. Web pages are not limited. OpenSSH git-serve is a separate process and is not covered.

PKGBUILD

Pushes compare simple assignments only. To also run makepkg --printsrcinfo you must set TAUR_PKGBUILD_ISOLATION=bwrap and install bubblewrap. The server will not fall back to running makepkg on the host. That sandbox is not a virtual machine.

TLS

TAUR_TLS=off is plaintext HTTP, and gRPC on TAUR_GRPC_BIND is plaintext HTTP/2. Put a proxy in front if you want TLS there. TAUR_TLS=acme is HTTP-01 in the process: HTTPS on TAUR_BIND, and gRPC uses that same certificate. It does not start without TAUR_DOMAIN and TAUR_ACME_ACCEPT_TERMS=yes, and it does not fall back to HTTP on the application port. SSH is separate. A Caddy snippet for this documentation site is Caddyfile in this branch. It does not start by itself.
